# Результат подготовки CodeSearchNet

Запуск: Python 3.12.3, pandas 2.3.3, datasets 4.8.5, pyarrow 25.0.1, seed 42.
Источник и ревизия: `data/raw/codesearchnet/python_functions.manifest.json`.

| Показатель | Значение |
|---|---:|
| Прочитано исходных записей | 10 144 |
| Корректный Python | 10 000 |
| Ошибки разбора | 144 |
| Удалено точных дубликатов | 0 |
| `clean_functions.csv` | 10 000 × 4 |
| `bug_detection_dataset.csv` | 14 743 × 5 |
| Класс 0 | 10 000 |
| Класс 1 | 4 743 |
| comparison_operator | 1 956 |
| arithmetic_operator | 1 838 |
| boolean_operator | 949 |
| Отклонено кандидатов мутаций при проверке | 27 |
| Коллизии мутированного кода | 0 |
| Функций без поддерживаемых операторов | 5 251 |
| Всего функций без принятой мутации | 5 257 |

Мутации не создавались принудительно. Сохранены все 10 000 исходных функций.
Clean и buggy имеют общий `source_id`; глобальных точных дубликатов нет.

Ошибки разбора исходников:

- 75 — общий `invalid syntax`, включая использование `async` как атрибута;
- 51 — Python 2 `print` без скобок;
- 13 — старый синтаксис `except Exception, e`;
- 2 — старые восьмеричные литералы;
- по 1 — генератор без требуемых скобок, распаковка параметров функции
  и другая синтаксическая ошибка с подсказкой про запятую.

Первый загрузчик на многопоточном сканере Parquet сохранял данные, но падал
при завершении Python. Он заменён последовательным чтением пакетов по 256
записей. Исправленный загрузчик успешно прошёл прогоны на 100 и 10 000
функциях. Два полных скачивания дали идентичный raw JSONL по SHA-256.

Ревью выявило ошибку расчёта позиций при Unicode-разделителях внутри строк;
она исправлена с регрессионным тестом. Аудит реального набора выявил случай
нескольких начальных docstring подряд; он также исправлен и покрыт тестом.
Полная тестовая группа: **23 теста прошли**. `pip check` не нашёл конфликтов.

Независимый аудит CSV подтвердил разбор всех 14 743 строк грамматикой
Python 3.10, отсутствие docstring и точных дубликатов, совпадение всех чистых
строк в двух файлах, связи с исходным JSONL и ровно один изменённый токен
в каждой паре. Результат: `data/processed/quality_audit.json`.

Команда сборки печатает **по 5 полных пар каждой категории**; они сохранены
в [bug_detection_dataset.examples.txt](../data/processed/bug_detection_dataset.examples.txt).
Несколько изменённых выражений из этих пар:

| source_id | Категория | Оригинал | Мутация |
|---|---|---|---|
| 008288 | comparison_operator | `props.object.signJoy[self.obj.id] == self.obj.sign` | `props.object.signJoy[self.obj.id] != self.obj.sign` |
| 003181 | arithmetic_operator | `Sx(mt, x) / Dx(mt, x)` | `Sx(mt, x) * Dx(mt, x)` |
| 009708 | boolean_operator | `x not in seen and not seen.add(x)` | `x not in seen or not seen.add(x)` |

`clean` означает исходный пример, а `buggy` — синтетическую замену оператора;
поведенческая корректность исходников и ошибочность замен не доказываются.
